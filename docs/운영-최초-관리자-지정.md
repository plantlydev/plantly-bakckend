# 운영: 최초 관리자 지정

첫 배포는 소셜 로그인 전용이다(`app.auth.local-login-enabled=false`). 관리자도 일반 회원처럼 네이버로 가입·로그인하고,
관리자 권한(`users.user_role = 'ADMIN'`)은 운영 DB 에서 일회성 SQL 로 준다. 관리자 권한을 주는 API·화면은 아직 없다.

## 절차

1. 관리자가 될 사람이 운영 사이트에서 **개인 네이버 ID** 로 가입한다.
   - 네이버 웍스 계정으로는 네이버 로그인을 할 수 없다(계정 체계가 별개다).
   - 이 네이버 계정에는 **2단계 인증을 켠다.** 계정이 털리면 관리자 권한도 같이 넘어간다.
2. 운영 DB 에서 그 회원을 확인한다. 이메일은 네이버가 준 이메일(연락처 이메일)이다.

   ```sql
   SELECT u.id, u.email, u.name, u.user_role, u.user_status, s.provider, s.created_at
   FROM users u
   JOIN social_account s ON s.user_id = u.id
   WHERE u.email = '<관리자 네이버 이메일>';
   ```

   정확히 한 행, `provider = 'NAVER'`, `user_status = 'ACTIVE'` 인지 본다.
3. 그 id 로 승격한다. 이메일이 아니라 **확인한 id 로** 지정한다.

   ```sql
   BEGIN;
   UPDATE users SET user_role = 'ADMIN' WHERE id = <확인한 id> AND user_role = 'MEMBER';
   -- 1 row 인지 확인한 뒤
   COMMIT;
   ```
4. 관리자는 **로그아웃 후 다시 로그인**한다. 역할은 로그인할 때 세션에 담기므로, 이미 로그인된 세션에는 반영되지 않는다.

## 하지 않는 것

- 이메일 도메인(`@plantly.co.kr`)을 보고 관리자 권한을 자동으로 주지 않는다. 네이버가 주는 이메일은 사용자가 바꿀 수 있는
  연락처 이메일이라 권한 근거가 될 수 없다.
- 관리자 해제도 같은 방식(`user_role = 'MEMBER'`)이다. 관리자가 늘어나면 권한 부여 API·감사 기록을 만든다.
